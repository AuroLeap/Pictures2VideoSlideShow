## 1. Executive summary

**Strengths (real ones, not politeness):**

- The Rust engine is genuinely well built. The pure-core / I/O-shell split the
  project preaches is actually practiced: `transform::ClipPlan`,
  `ffmpeg::resolve::pick`, `audio::delay_ms`, `interaction::should_prompt`,
  `location::choose_config_dir` are pure and exhaustively unit-tested, while
  process I/O lives in thin wrappers. Crash-safety (`.part` → atomic promote,
  Drop-cleanup, watchdog) is carefully engineered and *tested*.
- Documentation discipline is exceptional for a hobby-sized repo:
  one-fact-one-home is enforced, the quick reference really is the single source
  of truth, the architecture map is generated from code, and the SN→SR→LLR→TC
  traceability is maintained with zero orphans.
- The integration test suite tests behavior end-to-end through the built binary
  (corrupt inputs, read-only sources, atomic finalize, audio passthrough,
  encode profile via ffprobe) rather than mocking everything.

**Most critical issues found:**

1. **Licensing violation.** `Scripts/autocolor`, `Scripts/autogamma`,
   `Scripts/autotone` are Fred Weinhaus ImageMagick scripts licensed
   "free of charge for **non-commercial use, ONLY**" and requiring permission to
   redistribute — committed into an MIT-licensed repo. They are referenced only
   from one commented-out line. This is redistribution the license does not
   grant.
2. **Personal data committed.** `Scripts/ContReportPath` is a 3.6 MB CSV listing
   thousands of the maintainer's family photo/video paths (personal folder
   names included). It is referenced by nothing. If this repo is public, that is
   a privacy leak; either way it is 3.6 MB of junk in every clone — and it
   remains in git history even after deletion.
3. **A documented CLI feature silently does nothing.** Quick Reference §2:
   "`build` accepts `--output <name>` to build only one output definition."
   The code (`src/main.rs:135`) matches `Some(Commands::Build { .. })` and
   discards the value — a user asking for one output gets *all* of them
   (potentially hours of unwanted encoding), with no warning.
4. **SR-018 conformance gap.** SR-018 (Status=Verified) says files *and
   folders* whose **path** matches an ignore pattern are excluded. The code
   (`media::is_ignored`) matches the *file name only* — a pattern naming a
   private folder does not exclude the files inside it. The requirement is
   marked Verified by tests that only exercise file names.
5. **Whole-crate duplicate compilation.** `src/main.rs` re-declares every
   module (`mod config; mod ffmpeg; …`) that `src/lib.rs` also exports, so the
   entire engine is compiled twice (lib + bin), unit tests run twice, and
   `#[allow(dead_code)]` markers are scattered to silence one compilation's
   false positives (e.g. `SlideshowError::Processing` is marked "reserved for
   future use" while actually used).
6. **Dependency bloat.** `futures`, `once_cell`, `regex`, `lazy_static` are
   entirely unused; `tokio` (with `features = ["full"]`) exists solely to run a
   program that contains **zero** actual concurrency — every `async fn` in the
   codebase is async in name only.

## 2. Prioritized findings

### CRITICAL

#### C1. Non-commercially-licensed third-party scripts redistributed under MIT
- **Location:** `Scripts/autocolor`, `Scripts/autogamma`, `Scripts/autotone`
  (headers: "Copyright © Fred Weinhaus … available free of charge for
  non-commercial use, ONLY … To purchase the right to use … contact me.")
- **Problem:** The repo's `LICENSE` is MIT (grants commercial use and
  redistribution). Committing these scripts redistributes them in a context
  that grants rights their license forbids. Their only use is one *commented
  out* line (`PrepareMediaForDisplay.psm1:727`).
- **Why it matters:** This is the one finding with legal exposure. It also
  poisons the "this repo is MIT" claim for downstream users.
- **Fix:** Delete the three scripts (done). If the auto-color feature is ever
  revived, invoke a user-installed copy by documented instruction instead of
  vendoring. Note: the files remain in git history; a history purge
  (`git filter-repo`) is an owner decision (see §0).

#### C2. Personal data (family media inventory) committed
- **Location:** `Scripts/ContReportPath` — 3.6 MB CSV, rows like
  `"...\Family Photos and Videos\000 - <family member>'s Edited Photos\2023\...jpg"`.
- **Problem:** A personal file inventory with family names in folder paths,
  committed to a repo with a public GitHub remote. Referenced by no code
  (`ContReportPath` in `PrepareMediaForDisplay.psm1` is a *variable name*, not
  this file).
- **Why it matters:** Privacy; also repo bloat in every clone.
- **Fix:** Delete (done). History purge is an owner decision (destructive
  rewrite of published branches).

### HIGH

#### H1. `build --output <name>` is parsed, documented, and ignored
- **Location:** `src/main.rs:135`
  (`None | Some(Commands::Build { .. }) => run_build(...)`) vs
  `docs/quick-reference.md` §2 ("`build` accepts `--output <name>` to build
  only one output definition").
- **Problem:** The subcommand's `--output` value is never read. Every output
  definition is built regardless.
- **Why it matters:** Silent wrong behavior on a documented flag — exactly the
  "fail loudly, never silently" rule this repo commits to. Worst case is hours
  of unwanted encode time. It is also confusable with the *global*
  `-o/--output <dir>` flag (different meaning, same name).
- **Fix:** Implement the filter: select the named output definition, fail with
  a plain-language error naming the available definitions when there is no
  match. Add LLR/TC rows (SR-017) and an integration test. (Done.)

#### H2. SR-018 ignore matching is narrower than the Verified requirement
- **Location:** `src/media/mod.rs:101-111` (`is_ignored` matches
  `path.file_name()` only) vs `docs/requirements/system-requirements.csv`
  SR-018: "exclude files **and folders** whose **path** matches …
  Permutations: `target={file,folder}`", Status=Verified.
- **Problem:** A pattern intended to exclude a folder (`"PrivateAlbum"`) does
  not exclude files inside it unless each *file name* also contains the
  pattern. The verifying tests (`ignore_pattern_matches_case_insensitively_sr018`
  etc.) only exercise file names, so the gap was invisible to the harness.
- **Why it matters:** The stated purpose of SR-018 is "private albums are kept
  off the frame". This is a privacy-relevant conformance bug wearing a
  "Verified" badge — the worst kind of registry rot.
- **Fix:** Match patterns against the path *relative to `media_root`* (so a
  pattern in the user's root folder name can't nuke the whole album), keep
  case-insensitivity, add folder-target unit tests. (Done.)

#### H3. Entire crate compiled twice (bin re-declares the lib's modules)
- **Location:** `src/main.rs:9-21` (`mod config; mod error; … mod video;`)
  alongside `src/lib.rs` (`pub mod` for the same 13 modules).
- **Problem:** The binary does not use the library crate; it recompiles every
  module as its own copy. Consequences: double compile time for
  build/clippy/test, unit tests execute twice (the "lib 34 + bin 34" counts in
  status.md are the *same* tests twice), and dead-code analysis diverges
  between the two crates — hence misleading annotations like
  `src/error.rs:36` `#[allow(dead_code)] // reserved for future use` on
  `Processing`, which is *actively used* by `setup/mod.rs`.
- **Why it matters:** Cognitive load and misleading comments now; divergence
  risk later (a symbol can be live in one compilation and dead in the other).
- **Fix:** `main.rs` imports `slideshow_core::…` and declares no modules; drop
  the stale `allow(dead_code)`s that the unification exposes. (Done.)

#### H4. Unused and unjustified dependencies
- **Location:** `Cargo.toml:13-23`.
- **Problem:** `futures`, `once_cell`, `regex`, `lazy_static` — zero references
  anywhere in `src/` or `tests/`. `tokio = { features = ["full"] }` exists only
  for `#[tokio::main]`; there is no `.await` on anything real — every async fn
  merely calls other async fns. All actual parallelism is rayon; all subprocess
  I/O is `std::process`.
- **Why it matters:** "full" tokio is one of the heaviest dependency trees in
  the ecosystem — pure compile-time/supply-chain cost. The async signatures
  also actively mislead: they imply a concurrency model the program does not
  have.
- **Fix:** Remove all five; make `main`, `scan_and_index`, `execute` synchronous.
  (Done.)

### MEDIUM

#### M1. `exception_pattern` / `exception_threshold` are dead config
- **Location:** `src/config/mod.rs:23-24` (parsed, stored, never read
  anywhere); `docs/quick-reference.md` §4 documents them as functional
  ("Optional pattern that re-includes otherwise-ignored items").
- **Problem:** A user setting these gets *no effect and no warning* —
  documented behavior that does not exist (same failure class as H1).
- **Why it matters:** Violates both "fail loudly" and the doc-accuracy SRs
  (SR-003/SR-021) the project takes pride in.
- **Fix applied:** Quick Reference now states they are accepted for
  compatibility but **not implemented** in the Rust engine, and the §5 gap
  table lists them. Decide later: implement or remove the fields (see §0).

#### M2. Duplicate `[[outputs]].name` silently overwrites an output
- **Location:** `src/config/mod.rs::validate` (`Config::validate`); output path
  is `output_dir.join(format!("{}.mp4", output_def.name))` in
  `src/pipeline/mod.rs:180`.
- **Problem:** Two output definitions with the same `name` write to the same
  `<name>.mp4`; the second encode replaces the first with no error. Validation
  checks dims/fps/CRF but not name uniqueness.
- **Why it matters:** Hours of encode silently discarded; contradicts SR-017's
  "N distinct MP4s" acceptance criterion.
- **Fix:** Reject duplicate names in `Config::validate` with a plain-language
  message; unit test added; TC-007/LLR-003 registry rows extended. (Done.)

#### M3. `RUST_LOG` is documented but overridden
- **Location:** `src/logging.rs:13-17`; Quick Reference §2 ("`-v`/`--verbose`
  (or `RUST_LOG=debug`) increases logging").
- **Problem:** `Builder::from_default_env()` reads `RUST_LOG`, but the
  unconditional `.filter_level(level)` then overrides the global level, so
  `RUST_LOG=debug` without `--verbose` does nothing.
- **Fix:** Use the env filter with the chosen level as *default* only
  (`Env::default().default_filter_or(...)`), so `RUST_LOG` wins when set.
  (Done.)

#### M4. Stale BLOCKER narrative on a passing test
- **Location:** `tests/skip_and_continue.rs:99-108` — doc comment says
  "IGNORED — documents a confirmed SR-014 conformance gap (BLOCKER …)" but the
  test carries no `#[ignore]`, passes, and the described bug was fixed
  (`src/pipeline/mod.rs:290` guards `produced_total == 0`).
- **Why it matters:** A reader triaging failures will burn time reconciling a
  comment that describes a world that no longer exists.
- **Fix:** Comment rewritten to describe the regression-test role. (Done.)

#### M6. Two READMEs describe the project in parallel

- **Problem:** One-fact-one-home violation at the front door: which file GitHub

#### M7. Preflight/stats/bench probe `ffprobe` from bare PATH only
- **Location:** `src/preflight.rs:64` (`check_program("ffprobe", "ffprobe")`),

  configured/cached FFmpeg and prepends its dir to `PATH` — but only on the
  `build` path (`src/main.rs::run_build`).
- **Problem:** `validate`, `stats`, and `bench` never call `ensure_ffmpeg`, so
  with a cached/config-only FFmpeg install, `validate` reports ffprobe FAIL
  (and `stats` silently loses video metadata) even though `build` would work.
- **Why it matters:** `validate` exists to predict whether `build` will work;
  here it can disagree with reality in both directions.
- **Fix:** Not auto-fixed — the clean fix (resolve once in `main`, thread the
  resolved paths through) touches the SR-027 resolution contract; deferred

### POSITIVE / GOOD PRACTICES (keep doing these)

- **Crash-safety engineering:** `.part` → atomic `promote`, `Drop` kills the
  child and removes temps, watchdog turns a wedged ffmpeg into a *named*
  timeout error instead of a false success (`src/ffmpeg/mod.rs`), and the
  zero-frames guard refuses to finalize an empty MP4. All of it is tested.
- **Pure-decision extraction:** `timed_out`, `pick`, `should_prompt`,
  `choose_config_dir`, `delay_ms`, `ClipPlan` — the exact functions that need
  exhaustive tests are the ones that got them.
- **Determinism by design:** seeded per-image RNG (SplitMix64 from an FNV-1a
  path hash) with a deliberate note about keeping the RNG stream stable when a
  focus overrides the pan (`src/transform/mod.rs:131-133`). That comment is a
  model of "explain why at the non-obvious point".
- **Integration tests that prove claims:** encode profile verified via ffprobe
  (codec/pix_fmt/faststart), audio passthrough verified for mixed
  silent/audio-bearing albums, source tree fingerprinted byte-for-byte to prove
  read-only behavior.
- **Docs:** generated architecture map + Mermaid diagrams from code comments;
  quick-reference as enforced single source; honest "not implemented yet" gap
  table with workarounds; status.md session log with pasted evidence.
- **Supply-chain hygiene where it counts:** pinned FFmpeg release URL +
  SHA-256 verified *before* extraction; never runs an unverified binary; no
  admin/elevation required.

## 3. Recommendations and next steps

1. **Ship the license/privacy deletions** (C1, C2) and decide on a git-history
   purge. Until history is rewritten, the Weinhaus scripts and the personal CSV
   are still fetchable from the remote.
2. **Land the H1/H2/M2 correctness fixes** (this review's fix pass) — they are
   the gap between "the docs and registries say" and "the code does", which is
   this project's whole value proposition.
3. **Adopt the slimmed dependency set** (H4). After tokio removal the crate is
   honest about its execution model: rayon for CPU parallelism, blocking pipes
   for ffmpeg.
4. **Next feature investment should be `bulk_video_time_min` splitting in
   Rust** — it is the single remaining reason the 1,583-line untested
   PowerShell module must stay alive, and it is the top real-world risk
   (FAT32 4 GB wall) per the project's own constraints doc.
5. **Do a registry status-truth pass** (L14): statuses (Draft/Implemented/
   Verified, Automated flags) have lagged behind the code in several rows. The
   orphan checker verifies *links*, not *status honesty*; a quarterly manual
   sweep or a small status-consistency lint would close that hole.
6. **Unify CI truth** (L13): either adapt kit `check.yml` to call the Rust
   harness or delete it in favor of `ci.yml`, so a green checkmark has exactly
   one meaning.
7. **Decide the fate of dead config** (M1): implement `exception_pattern`/
   `exception_threshold` in the Rust scanner or delete the fields in a major
   config version. Documented-but-inert is the worst of both.
8. **Consider `validate` parity with `build`** (M7): resolve FFmpeg/ffprobe
   once in `main` and hand the paths down, so `validate`'s verdict always
   matches what `build` would experience.
